30명과 교사 1명인 대표 반에서 50분을 가상 시간으로 실행하고, 같은 활동을 7개 반이 순차 진행하는 하루로 환산했습니다. 기존 글은 보드 10개×30개, 과제 5개×30개, 익명 의견 30개이며, 새 수업 중 학생마다 보드 글 3개를 작성하고 교사가 각각 확인했습니다. 게시·확인은 16초 간격으로 엇갈려 발생하고, 학생은 게시 후 자신의 화면을 즉시 갱신합니다.

| 지표 | v46 | v47 |
|---|---:|---:|
| 하루 환산 HTTP 요청 | 105,637 | 67,207 |
| 하루 환산 SQL 실행 | 702,919 | 170,366 |
| 하루 환산 SELECT 반환 행 | 17,942,449 | 932,036 |

운영 서버에 부하를 보낸 시험이 아닙니다. 실제 Worker 처리 코드와 로컬 SQLite를 실행했습니다. 반환 행은 D1의 과금 지표인 `rows_read`가 아니며, Worker 실행 인스턴스가 나뉘면 캐시 재사용 정도가 달라집니다. 실제 D1 사용량·파일 전송·로그인·사용자 새로고침·네트워크 지연은 운영 환경에서 추가 확인해야 합니다. 무료 한도 내 운영을 보장하는 수치는 아닙니다.

학생별 비공개 제출물, 익명 작성자 숨김, 교사 권한, 캐시 복사본 간 격리, 게시·반려·삭제 반영, 변경 없는 응답, 학생·교사의 추가 HTTP 요청 제거와 이전 응답 방식 호환 검증을 통과했습니다.

배포 후 기존 사이트에서 `Ctrl+Shift+R`로 새 파일을 불러옵니다. `/api/health`의 `release`는 `2026-10-15-v47`입니다.

## v46 — 반복 요청 줄이기 (2026-10-12)

- 일반 클래스의 변경 확인 간격은 10초를 유지합니다. 학생 접속 기록을 DB에 저장하는 간격은 1분으로 줄였습니다.

- 다른 탭을 보거나 인터넷이 끊기면 자동 확인을 멈춥니다. 화면으로 돌아오면 다시 확인합니다.
- 자동 확인이 실패하면 재시도 간격을 늘립니다. D1 하루 한도 초과 메시지를 받은 경우 다음 UTC 자정까지 반복 요청을 멈춥니다.
- DB 구조의 정상 여부는 요청마다 읽지 않고 실행 인스턴스 안에서 1분간 재사용합니다. 로그인과 게시글의 접근 권한은 계속 요청마다 확인합니다.
- 별도 DB 생성·이전은 필요 없습니다. 기존 DB와 파일 저장소 연결을 유지합니다.

### 반영과 확인

1. GitHub에 이미 반영된 경우 ZIP을 다시 업로드할 필요가 없습니다. 수동 반영 시 이 ZIP의 파일을 저장소 최상위에 덮어씁니다.
2. 기존 D1·R2 바인딩과 환경변수는 그대로 유지합니다.
3. 배포가 끝나면 기존 사이트 탭을 닫았다가 다시 열거나 강력 새로고침(Ctrl+Shift+R)을 합니다.
4. `/api/health`의 `release`가 `2026-10-12-v46`인지 확인합니다. 오늘의 D1 한도가 이미 소진됐다면 읽기 가능 여부는 내일 한국 시간 오전 9시 이후 확인합니다.
5. 한도가 초기화되면 수업 사이트를 사용하기 전에 학생 글부터 백업합니다.

### 비교 측정의 범위

30명과 교사 1명, 7개 반을 각 50분씩 순차 운영하는 가상 시간 로컬 시험입니다. 실제 Worker 처리 코드와 SQLite로 실행했으며 운영 서버에는 부하를 보내지 않았습니다.

- 참여방 기본 조회: 108,500 → 65,100회 (40% 감소)

# 사랑스런(Learn) 수업시간 — Cloudflare 고속 버전

기존 화면 구조와 디자인은 유지하고, 느린 Google Apps Script 백엔드를 Cloudflare로 교체한 버전입니다.

## 저장 위치

- 홈페이지: Cloudflare Workers Static Assets
- 교사·클래스·학생·글: Cloudflare D1
- 첨부파일: Cloudflare R2
- 로그인 세션: Cloudflare D1

첨부파일은 Base64 문자열로 변환하지 않고 R2에 바로 업로드합니다. 화면은 10초마다 작은 변경번호만 확인하고, 변경된 경우에만 새 자료를 받아옵니다. 휴대폰에서 다른 화면을 보다가 돌아온 경우에는 기다리지 않고 즉시 변경 여부를 확인합니다.

새 공지·제출·보드 글이 생겨도 전체 로딩 화면으로 전환하지 않고 현재 위치를 유지한 채 백그라운드에서 내용을 갱신합니다.
학생이 과제나 보드 글을 직접 게시·수정·삭제한 직후에는 10초 확인 주기를 기다리지 않고 즉시 최신 자료를 다시 받아 화면에 반영합니다.
교사의 보드 확인·반려 상태는 학생 본인의 상태만 heartbeat 응답에 함께 담아 10초 이내에 별도로 동기화합니다. 다른 학생에게는 이 상태가 전달되지 않습니다.
학생 또는 교사 로그인이 만료되면 브라우저에 남은 만료 세션을 즉시 삭제하고 해당 로그인 화면으로 자동 이동합니다.

데이터베이스의 부가 기능 표를 업데이트하는 중 문제가 생기더라도 기존 교사 로그인과 기존 클래스 접근은 차단하지 않습니다. `/api/health`의 `databaseReady`와 `featureSchemaReady`를 함께 확인하면 D1 연결 문제와 기능 업데이트 문제를 구분할 수 있습니다.

## 처음 배포하기

1. 이 폴더의 **내용 전체**를 GitHub 저장소 최상위에 올립니다.
2. [Cloudflare 대시보드](https://dash.cloudflare.com/)에서 `Workers & Pages`를 엽니다.
3. `Create application` → `Import a repository`를 선택합니다.
4. GitHub의 `salang_classroom` 저장소를 연결합니다.
5. Worker 이름은 `salang-classroom`으로 지정합니다. `wrangler.jsonc`의 이름과 같아야 합니다.
6. 배포 명령은 `npm run deploy`로 지정하고 `Save and Deploy`를 누릅니다.
7. 첫 배포가 끝나면 Worker의 `Settings` → `Variables & Secrets`로 이동합니다.
8. 런타임 암호 변수 `TEACHER_SETUP_KEY`를 추가합니다. 20자 이상의 추측하기 어려운 값으로 정하고 `Encrypt`를 켭니다.
9. 다시 배포한 뒤 아래 주소로 교사 계정을 처음 만듭니다.

   `https://내주소.workers.dev/#/teacher/signup`

교사 회원가입을 처음 실행할 때 D1 표가 자동 생성됩니다. 학생에게는 클래스별 로그인 링크나 로그인표 QR을 전달하면 클래스 코드가 자동 입력됩니다. 계정을 처음 설정하는 학생은 초기 4자리 비밀번호로 닉네임과 새 비밀번호를 등록합니다.

클래스 코드는 한글, 영문, 숫자, 밑줄(_), 하이픈(-)을 섞어 3~16자로 만들 수 있습니다. 예: `사랑1반`, `도덕수업`, `LOVE01`

## 아이디어 구름과 수업 타이머

- 교사는 `아이디어 구름` 질문을 만들고 의견 작성을 열거나 마감할 수 있습니다.
- 학생은 100자 이내의 의견을 여러 개 올리고 자기 의견만 수정·삭제할 수 있습니다.
- 의견은 학생에게 항상 익명으로 보이며, 교사는 `익명 보기 / 작성자 보기`를 전환할 수 있습니다.
- 학생은 각 의견을 개별 또는 1~12모둠으로 지정하고, 작성 순서나 모둠별로 묶어 볼 수 있습니다.
- 교사는 클래스 상단에서 활동명과 시간을 정해 타이머를 시작·종료할 수 있고 학생 화면에도 같은 종료 시각이 표시됩니다.
- 학생 로그인표를 인쇄하면 클래스 코드·출석번호·초기 4자리 비밀번호와 해당 반 코드가 입력된 로그인 QR이 함께 표시됩니다.

## 강의용 1회성 참여방

- 교사 메인에서 `1회성 참여방`을 만들고 2시간, 6시간, 12시간, 24시간, 3일, 7일 중 이용 시간을 정합니다.
- 화면에 표시되는 QR을 참여자가 찍으면 이름·학번·비밀번호 없이 익명으로 바로 들어옵니다.
- 한 참여방에서 `의견 나눔`, `파일 보드`, `아이디어 구름`을 함께 사용할 수 있습니다.
- 한 참여방 안에 이름이 다른 파일 보드를 여러 개 만들 수 있습니다. 교사는 보드를 추가·이름 수정·삭제하고, 참여자는 원하는 보드를 골라 글과 파일을 올립니다.
- 참여자는 자기 글만 수정·삭제하고 자기 파일만 내려받을 수 있습니다. 다른 참여자의 파일은 화면에서 미리보기만 가능합니다.
- 교사는 참여방에 직접 공지·파일·아이디어를 올리고 자기 게시물을 수정할 수 있습니다. 공지와 파일 보드 게시글에는 제목을 붙일 수 있습니다. 모든 참여자 글과 파일을 확인·삭제하며, 강의가 끝나면 참여를 즉시 마감하거나 참여방 전체를 삭제할 수 있습니다.
- 참여방 이름은 만든 뒤에도 수정할 수 있으며 기존 QR·참여 링크와 게시물은 그대로 유지됩니다.
- 선생님이 올린 안내·자료·제시어는 참여자 글과 분리된 영역에서 접거나 펼쳐 볼 수 있고, 자동 갱신 후에도 접은 상태가 유지됩니다.
- 교사 메인의 `1회성 참여방 목록`도 접거나 펼칠 수 있으며 마지막 상태가 브라우저에 저장됩니다.
- 기존 참여방의 파일 글은 첫 번째 `파일 보드`로 자동 연결되고, 기존 제목 없는 글도 그대로 표시됩니다.
- 이용 시간이 끝난 방은 자동으로 새 글 접수가 중단됩니다. 정규 클래스와 학생 계정 자료에는 영향을 주지 않습니다.

클래스 카드 또는 클래스 상단의 `클래스 정보 수정`에서 클래스명·학교명·과목을 수정할 수 있습니다. 학생 로그인과 기존 자료 연결에 사용되는 클래스 코드는 변경되지 않습니다.

정규 클래스의 보드에서는 선생님 안내를 접거나 펼칠 수 있습니다. 학생 카드는 화면에서 출석번호를 다시 확인해 1번부터 차례대로 정렬되며, 작성 인원도 함께 표시됩니다.

학생은 보드 글을 올리거나 수정할 때 제목을 함께 입력합니다. 제목은 학생 카드, 학생 상세 팝업, 교사 보드 관리 화면에 표시되며 기존 무제목 게시물은 `제목 없는 글`로 안전하게 표시됩니다.

- 개별 첨부파일: 미리보기 창의 `Google Drive로 보관`
- 과제 제출물: 제출물 창의 `Drive로 일괄 보관`
